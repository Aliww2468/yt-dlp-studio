# 架构与接口说明

本文面向维护人员，描述 v1.1.1 的现有实现。接口是桌面应用的内部接口，未承诺作为稳定的公共 API 提供。

[返回项目首页](../README.md) · [开发与发行](development.md)

## 1. 运行结构

```text
用户
 └─ yt-dlp Studio.exe
     ├─ Windows 窗口、托盘及单实例检查
     ├─ WebView2 → HTML / CSS / JavaScript 界面
     └─ Node.js 本机后台
         ├─ 设置、历史记录和任务队列
         ├─ yt-dlp：解析与下载
         └─ FFmpeg / FFprobe：媒体处理及检查
```

桌面外壳采用 .NET 8 WinForms 和 Microsoft WebView2。后台使用 Node.js 内置模块，前端为原生 HTML、CSS 和 JavaScript。

WebView2 自身会创建浏览器、渲染、GPU 或其他辅助进程，因此“单实例”与“单一操作系统进程”不是同一概念。

## 2. 启动与实例控制

桌面入口首先执行单实例检查，通过后才创建数据目录和主窗口。

互斥对象使用当前 Windows 用户 SID 作为名称的一部分，位于 Local 命名空间，因此作用范围为同一用户的当前 Windows 登录会话。名称不依赖软件目录，安装版和便携副本共用此限制。

使用非阻塞方式获取互斥锁。锁已被占用时，本次启动显示通知并返回，不创建新的后台。原进程异常退出导致锁被遗弃时，新进程可以接管锁。

兼容检查还会查看同会话中已初始化的旧桌面实例及其会话 PID。该检查用于在新版本启动时发现已有旧实例，不能将旧可执行文件改造成新版启动器，也不保证旧版本主动启动时遵守新规则。

应用退出时释放锁。单实例通知本身会短暂占用本次启动进程，用户确认后该进程结束。

## 3. 后台连接与端口

桌面启动器先读取上次使用的端口，并尝试连接对应本机服务。连接后通过 bootstrap 返回的软件根目录确认服务是否属于当前目录。

若不能复用服务，桌面启动器启动 Node.js，显式设置：

| 环境项 | 作用 |
| --- | --- |
| PORT | 本次本机后台端口 |
| YTDLP_NO_TRAY=1 | 避免再启动旧的开发托盘辅助程序 |
| YTDLP_DATA_DIR | 当前桌面目录下的数据路径 |

默认端口为 47831。桌面启动器遇到端口占用时，会在其候选范围内尝试可用端口。直接运行 server.mjs 的开发模式不使用相同的端口重试封装。

## 4. 依赖选择

桌面程序优先使用根目录 bin/node.exe；该文件不存在时，读取 dependencies.json 中记录的 Node.js 路径。桌面启动阶段只确认路径有效且文件存在，兼容性检查由安装脚本承担。

后台通过 lib/dependencies.mjs 选择下载工具：

- 若本地 bin/yt-dlp.exe 存在，优先使用本地引擎。
- 若本地引擎不存在，使用记录的外部引擎路径。
- 本地 FFmpeg 和 FFprobe 都存在时使用本地目录，否则使用记录的外部目录。
- 配置损坏或路径不是绝对路径时，提供重新运行安装器的修复提示。

环境检测执行版本命令并缓存结果。“重新检测”刷新版本状态，不重新搜索整个系统 PATH，也不自动补齐组件。

## 5. 队列与持久化

队列在后台内存中管理，变更后保存到 jobs.json。每个任务保存 URL、输出目录、选项快照、状态、进度、近期日志及文件路径。

调度器每次只执行一个队列任务。创建任务后查找第一个等待任务，启动 yt-dlp，并解析下载进度和输出路径标记。进程成功退出后才标记为已完成。

重试保留原选项，重新排队并清理错误与近期日志。删除记录不会删除对应媒体文件。后台启动时，将上次仍在执行链路中的任务转为已中断。

界面通过 Server-Sent Events 接收任务列表更新；连接每 20 秒发送一次心跳。下载进度通过 yt-dlp 的参数控制为至多每半秒输出一次相关更新，而不是界面持续高频轮询全部任务。

## 6. 本机 HTTP 接口

所有请求均受到 Host/Origin 检查。除 bootstrap 外，API 请求还需使用当前会话令牌；常规请求通过 X-App-Token 头提供，事件流使用 token 查询参数。

| 方法 | 路径 | 主要输入 | 主要输出或作用 |
| --- | --- | --- | --- |
| GET | /api/bootstrap | 无请求体 | 应用标识、后台 PID、会话令牌、设置、任务和环境 |
| GET | /api/events | token 查询参数 | SSE 任务列表及心跳 |
| POST | /api/settings | outputDir、advanced、theme、compact | 保存并返回设置 |
| POST | /api/environment | 空对象 | 刷新下载组件版本信息 |
| POST | /api/inspect | url、options | 解析单个链接并返回媒体摘要 |
| POST | /api/jobs | urls、options | 创建 1–50 条任务，返回任务 ID |
| POST | /api/job-action | id、action | cancel、retry 或 remove |
| POST | /api/open-folder | id 或 outputDir | 创建并打开对应输出目录 |
| POST | /api/pick-folder | 空对象 | 开发网页入口的文件夹选择结果 |
| POST | /api/update | 空对象 | 更新 yt-dlp 并返回环境状态 |
| POST | /api/shutdown | 空对象 | 检查任务状态后退出后台 |

普通 POST 请求体按 JSON 解析，输入文本有大小上限。操作失败通常返回带 error 字段的 JSON；Host/Origin 或令牌不符合要求时返回 403。不支持的方法返回 405，未实现路径返回 404。

bootstrap 的令牌提供方式是本机桌面会话机制的一部分，不应被视为面向公网用户的身份认证方案。

## 7. 桌面消息桥

正式桌面界面通过 WebView2 消息桥执行两类原生操作：

- pick-folder：打开 Windows 文件夹选择器。
- shutdown：在保存和状态检查后关闭后台及窗口。

请求携带唯一 ID，结果通过相同 ID 关联。主题变更使用独立 theme 消息更新原生窗口配色。桌面程序仅处理来自当前本机应用来源的消息。

普通外部链接交由系统浏览器处理。界面本身的主导航限制在应用所属本机来源中。

## 8. 引擎更新

应用本地拥有的 yt-dlp 使用自身更新命令。若当前复用外部共享引擎，则执行依赖脚本的 UpdateEngine 路径，将新版下载至本地 bin，再切换为该副本。

更新期间不启动新的队列任务；下载或解析等操作未结束时，更新请求会被拒绝。此设计不承担 GUI 自身、Node.js、.NET 或 FFmpeg 的自动版本升级。

## 9. 退出与错误恢复

主窗口的最小化或用户关闭操作默认隐藏窗口。正式退出路径先请求后台停止，并在活动任务、排队、解析或更新期间拒绝退出。

桌面初始化失败时，程序记录错误并尝试关闭由它启动的后台。若操作系统或用户强制结束进程，恢复依赖下次启动时的中断状态处理，不构成事务式恢复保证。
