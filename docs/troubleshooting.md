# 故障排查与常见问题

适用版本：yt-dlp Studio v1.1.1。

[返回项目首页](../README.md)

## 1. 排查顺序

建议先判断问题发生的阶段：安装、启动、链接解析、媒体下载或后处理。不同阶段使用的组件和网络路径并不完全相同。

1. 确认使用的是正式安装包或完整便携包。
2. 在“设置 → 下载引擎”查看版本和就绪状态。
3. 记录界面提示或任务详情中的实际错误。
4. 按本文对应条目处理。
5. 若仍无法解决，按文末格式提交问题。

## 2. 安装器下载失败

**现象：** 安装窗口显示连接超时、下载失败、文件校验失败或无法获取发布信息。

安装器可能需要访问 Microsoft、nodejs.org、GitHub 及其下载服务。能够访问某个视频站点，不代表可以访问这些组件分发服务。

请检查网络、磁盘空间和安装窗口中的具体错误，然后重试。校验失败时不应继续使用该次下载文件；安装器会停止这一轮安装并尝试清理临时目录。若网络不便于在线补齐组件，可选择便携版，但目标电脑仍需 WebView2 Runtime。

高级选项中的代理地址不会配置安装器自身的下载连接。

## 3. 提示缺少 .NET 或 WebView2

安装版使用 .NET Desktop Runtime 8 x64。普通 .NET Runtime、其他主版本或不同架构不一定满足要求。请优先重新运行安装器检查环境。

WebView2 Runtime 与 Edge 浏览器不是同一项部署条件。缺少 Runtime 时，可重新运行安装器，或从 [Microsoft 官方页面](https://developer.microsoft.com/microsoft-edge/webview2/) 安装 Evergreen Runtime。

便携版包含 .NET，但不包含 WebView2 Runtime。安装器对自定义位置中的 .NET 检测范围有限，详见[安装说明](installation.md)。

## 4. 提示缺少 Node.js 或组件路径无效

**常见原因：**

- 只复制了主程序 EXE，未保留完整发行目录。
- 安装版复用的外部 Node.js 或下载工具已被移动、卸载。
- 从另一台电脑复制了含旧绝对路径的 `dependencies.json`。
- 组件配置文件损坏。

安装版请重新运行安装器修复。便携版请完整重新解压至可写目录。不要把“重新检测”视为安装操作：它只检查当前可用路径，不会自动下载缺少的组件。

“安装下载组件.cmd”只负责补齐本地 yt-dlp、FFmpeg 和 FFprobe，不负责安装 .NET、WebView2 或 Node.js。

## 5. 提示软件已在运行，但看不到窗口

窗口可能已经最小化或关闭至托盘。请先检查任务栏及隐藏托盘图标区域，再使用托盘菜单打开主窗口。

v1.1.1 的重复启动行为是显示提示并取消新启动，不会自动恢复原窗口。不同目录中的安装版和便携版在同一 Windows 登录会话中共用单实例限制。

如果原实例仍在启动或尚未完成退出，请等待其结束。必要时可在任务管理器确认进程的可执行文件路径。结束进程前应确认没有需要保留的下载或处理任务。

旧版可执行文件本身不具备新版的全部互斥逻辑。升级使用时应退出旧版，并避免混用不同版本的启动入口。

## 6. 界面显示连接失败或启动失败

桌面程序启动本机 Node.js 后台，再通过 WebView2 加载界面。默认使用 127.0.0.1:47831；桌面启动器在端口冲突时会尝试其他候选端口。

请检查：

- 软件目录是否具有写入权限。
- `server.mjs`、`public`、`lib` 和组件目录是否完整。
- Node.js 路径是否仍然可用。
- `data/desktop-error.log` 是否记录了实际异常。

不要直接通过双击 `public/index.html` 代替应用启动。该文件依赖本机服务提供接口，不能作为独立网页完整工作。

## 7. 无法解析链接

应用仅接收不含用户名和密码的 HTTP/HTTPS 链接。请确认链接完整，并在普通浏览器中检查目标页面是否仍可访问。

可能原因包括媒体已删除、站点要求登录、区域或网络限制、站点结构变化以及 yt-dlp 暂不支持该来源。可以先更新 yt-dlp，再重新解析。需要登录状态时，可主动启用浏览器 Cookie 选项。

多个链接输入时，解析按钮仅处理第一条，因此第一条解析成功不代表后续链接均可下载。

## 8. 下载失败或进度长时间不变

任务可能处于下载、等待或后处理阶段。请先查看状态文本和任务详情。

- 等待中：前方任务尚未完成，队列按顺序执行。
- 正在下载但百分比缺失：源站可能未提供总大小。
- 进度从较低数值重新开始：可能开始下载另一音轨、视频流或列表项目。
- 正在处理：可能正在合并、转换或写入字幕与媒体信息。
- 下载失败：请查看近期日志中的错误原因。

应用中的“重试”沿用原任务选项。修改高级选项后，如果希望使用新的网络或格式配置，应创建新任务。

## 9. 视频只有声音、不能播放或格式不符合预期

容器扩展名与音视频编码不是同一概念。MP4 模式会优先选择 H.264/AAC，但不强制把所有内容重新编码为统一格式。

请检查实际文件是否已经处理完成，并确认播放器支持文件中的编码。可以尝试其他可用格式或画质。某些来源本身只提供音频，或其视频流提取失败，应结合日志判断。

## 10. 字幕、封面或浏览器 Cookie 不生效

字幕和封面必须由源站提供。自动字幕选项只下载源站已有自动字幕，不进行本地字幕生成。字幕嵌入还受输出容器和 FFmpeg 支持情况影响。

Cookie 读取需要主动选择浏览器。数据库占用、系统加密和站点验证都可能使读取失败。请查看实际错误，避免将“浏览器已经登录”直接理解为下载工具一定能够读取该登录状态。

## 11. 无法打开下载目录

任务中的目录按钮打开的是该任务保存的输出目录。请核对路径是否存在、驱动器是否在线以及当前用户是否有权限。

可以在“任务详情”中查看保存位置，并手动通过资源管理器定位。更改默认下载文件夹不会自动修改历史任务目录。网络盘、移动硬盘或目录迁移后，原路径可能不再有效。

## 12. 关闭窗口后仍有后台进程

这是当前桌面版的预期行为：关闭和最小化会收起至托盘。完全退出须使用托盘“退出”或“设置 → 退出应用”。

任务管理器中可能同时存在：

| 进程 | 作用 |
| --- | --- |
| yt-dlp Studio | 桌面窗口和托盘 |
| node | 本机下载服务 |
| msedgewebview2 | WebView2 浏览器、渲染、GPU 或辅助进程 |
| yt-dlp、ffmpeg、ffprobe | 解析、下载、转换或检查媒体时按需运行 |

单实例检测限制桌面应用实例，不会将这些不同职责的工作进程合并成一个。

## 13. 安装器很小，为什么磁盘仍有较大占用

轻量安装器不内置前置组件，但运行时仍然需要这些组件。环境不完整时，安装过程会下载缺少的文件；下载内容、WebView2 缓存和历史记录也会增加磁盘占用。

开发目录中的 `build`、`release` 和测试输出属于开发、打包或验证产物，不是普通用户安装时必需的全部内容。不能用整个开发目录大小推算正式安装体积。

## 14. 提交问题的建议格式

请通过 [Issues](https://github.com/Aliww2468/yt-dlp-studio/issues) 提交以下信息：

```text
软件版本：
Windows 版本与架构：
安装方式：普通安装版 / 便携版 / 源码运行
下载引擎版本：
问题发生阶段：
复现步骤：
预期结果：
实际结果：
已尝试的处理方式：
脱敏后的错误信息：
```

公开日志前应检查个人目录、带签名的下载链接、代理账号、Cookie 和其他认证信息。不要直接上传整个 data 目录。无法公开的媒体链接可用站点名称和问题特征说明，并明确无法提供公开复现链接。
