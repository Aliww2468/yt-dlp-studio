# 数据与网络说明

适用版本：yt-dlp Studio v1.1.1。

[返回项目首页](../README.md)

## 1. 数据存储位置

桌面版默认将设置、历史和 WebView2 用户数据保存于软件目录下。普通安装版的软件根目录为：

```text
%LOCALAPPDATA%\Programs\yt-dlp Studio
```

便携版的软件根目录为用户解压目录。开发人员可以通过后台环境变量指定其他数据目录；该方式不改变正式桌面版的默认布局。

| 路径 | 用途 | 迁移说明 |
| --- | --- | --- |
| `data/settings.json` | 主题、紧凑列表、默认目录及高级配置 | 退出应用后可备份；包含的绝对路径需自行核对 |
| `data/jobs.json` | 任务记录、原任务选项、近期日志和文件路径 | 可以备份，但迁移后不自动重写路径 |
| `data/webview/` | WebView2 用户数据及缓存 | 不属于媒体下载文件；迁移时通常不必复制 |
| `data/desktop-session.json` | 当前桌面实例的 PID、窗口及运行状态 | 临时运行信息，不宜作为个人配置迁移 |
| `data/desktop-port.txt` | 上次桌面后台端口 | 由应用维护 |
| `data/desktop-error.log` | 桌面启动失败等异常 | 排查时按需读取并脱敏 |
| `dependencies.json` | 安装版采用的外部组件绝对路径 | 仅对相应电脑和组件位置有效 |
| `downloads/` | 默认下载目录 | 用户可以在界面中更改 |
| `installed-files.txt` | 安装版的应用文件清单 | 卸载器使用，不宜手工改写 |

设置和历史以普通 JSON 文件存储，不属于加密凭据存储。高级代理地址及任务选项可能包含个人信息。

## 2. 数据保存与恢复

配置修改后，界面会显示保存状态。新任务保存提交时的选项副本，因此后续设置修改不会追溯应用于旧任务。

后台重新启动时，之前仍处于等待、下载、处理或取消过程的任务会标记为“已中断”，需要用户决定是否重试。程序不会将所有中断任务自动恢复为下载中。

历史记录仅描述任务和路径，不是下载文件的备份。“移除记录”不会删除文件；反过来，手动删除文件也不会自动删除历史记录。

## 3. 备份和迁移

建议按以下顺序备份：

1. 结束下载、解析和更新操作。
2. 从托盘或设置页面完全退出应用。
3. 备份 `data/settings.json`、`data/jobs.json` 及需要保留的媒体文件。
4. 记录默认保存目录和外部组件来源。
5. 在目标环境重新安装或完整解压，再按需恢复个人数据。

如果更换盘符、Windows 用户或目录位置，应检查设置及历史中的绝对路径。安装版的依赖配置应由目标环境中的安装器重新生成，不建议直接沿用原电脑路径。

## 4. 本机服务与访问边界

应用后台默认监听 `127.0.0.1`，不以局域网服务形式公开。界面通过本机 HTTP 接口访问后台，通过事件流接收任务状态。

当前实现检查请求 Host 和 Origin，并对常规 API 操作验证当前会话令牌。界面脚本和样式从应用自身提供的资源加载。桌面窗口限制导航到其本机服务地址，用户主动打开的外部链接交给系统浏览器处理。

这些措施用于约束当前应用的访问方式，不表示它提供多用户服务器级别的身份认证或安全隔离。不要直接将本机端口转发为公网服务。

## 5. 外部网络请求

软件本地运行不意味着完全离线。可能发生以下外部连接：

| 场景 | 连接对象 |
| --- | --- |
| 解析或下载媒体 | 用户提交的媒体站点及其内容分发服务 |
| 显示解析预览封面 | yt-dlp 返回的 HTTP/HTTPS 图片地址 |
| 安装 .NET 或 WebView2 | Microsoft 的发布元数据及下载服务 |
| 安装 Node.js | nodejs.org 分发服务 |
| 安装或更新 yt-dlp | yt-dlp GitHub Releases 及资源下载服务 |
| 安装 FFmpeg | yt-dlp/FFmpeg-Builds GitHub Releases 及资源下载服务 |
| 首次桌面源码构建 | NuGet 包源 |
| 主动打开参考链接 | 相应官方项目页面 |

当前应用代码没有实现用户账户注册、云端历史同步或单独的统计上报服务。所调用系统运行时和第三方工具具有各自的行为及设置，本文不替它们作统一隐私承诺。

## 6. Cookie、代理与日志

浏览器 Cookie 读取默认关闭。用户选择具体浏览器后，yt-dlp 才会尝试读取并使用相应 Cookie。应用自身不要求用户在界面中输入站点密码。

日志可能包含媒体链接、文件名、本地路径、站点错误、代理相关信息或临时访问地址。对外分享前，应只保留必要片段并进行脱敏。

不要上传整个 `data` 目录、浏览器用户数据目录或原始 Cookie 文件。源码仓库的忽略规则用于排除常见本地数据，但手动打包和手动上传时仍需检查文件范围。

## 7. 卸载后的数据

安装版卸载会保留个人设置和下载文件，系统共享组件也不随应用卸载。保留数据的原因是避免将应用卸载等同于删除用户内容。

如果用户需要彻底清理本机数据，应先确认备份范围和实际存储位置，再自行处理剩余目录。媒体文件可能位于默认目录之外，不能只检查安装目录。
