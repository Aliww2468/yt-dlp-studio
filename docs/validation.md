# 验证记录与已知限制

适用版本：v1.1.1。本文区分自动检查、受控测试和实际界面验证，避免将不同层次的证据混为一谈。

[返回项目首页](../README.md)

## 1. 构建和发行文件

- 自包含桌面版与依赖系统运行时的桌面版均已完成 Release 构建。
- 轻量安装器和完整便携归档均已生成。
- 安装器的解压验证路径已成功执行。
- 发行归档中的相关程序和源码文件已与本地对应内容进行校验。
- GitHub v1.1.1 资产上传后，大小及 SHA-256 与本地发行文件一致。

这些检查证明构建和上传内容的一致性，不等于在所有 Windows 设备上完成安装验证。

## 2. JavaScript 自动检查

现有测试运行结果为 15 项通过，包括：

| 类别 | 覆盖内容 |
| --- | --- |
| 参数与链接 | URL 协议、参数边界、高级开关、解析模式 |
| 本机访问限制 | 未授权及跨来源写入请求的拒绝 |
| 真实媒体处理 | 本地生成媒体的解析、视频下载、MP3 转换及 FFprobe 检查 |
| 生命周期 | 已传输数据后的取消与重试、失败反馈、重启后的记录保留 |
| 文件与记录 | 移除历史记录后保留媒体文件 |
| 依赖路径 | 外部路径复用、本地更新优先、损坏配置的修复提示 |
| 开发托盘 | 辅助托盘单实例、随后台退出清理 |

真实媒体测试使用本地生成的测试文件和本机 HTTP 服务，不代表 YouTube、Bilibili 或其他远程站点已逐一通过验证。

## 3. 安装器依赖检查

已验证本机已有真实组件时能够复用路径，不额外下载或复制组件。

以下分支使用受控测试数据验证程序流程：

- 缺少 .NET、WebView2、Node.js、yt-dlp 和 FFmpeg 时进入相应补齐路径。
- 组件补齐后的再次执行不重复下载。
- 网络失败会停止该轮安装。
- 校验值不匹配不会将安装标记为组件就绪。
- 失败后的临时目录清理。

受控测试没有在干净系统上真实安装全部 Microsoft 运行时，不能替代全新 Windows 环境验证。

## 4. 桌面与单实例检查

已实际确认：

- 精简版桌面程序在已有依赖环境中成功启动并加载界面。
- 软件目录未复制已有工具时，后台能够识别并使用已记录的组件路径。
- 从另一份目录重复启动会显示“软件已在运行，本次启动已取消”。
- 重复启动不会创建新的应用数据目录或第二个下载后台。
- 关闭通知后，本次启动进程退出，原实例保持运行。
- 隔离测试中同时启动 8 个进程时仅有一个获得实例锁。
- 锁拥有者正常退出或崩溃后，可以重新获取锁。

早期版本还执行过原生文件夹选择器打开与取消、窗口隐藏与恢复、设置页面退出等实际操作检查。当前版本的重复启动行为已改为通知后取消，早期“再次启动自动恢复窗口”的记录不能视为现行行为。

## 5. 资源占用记录

一次本机空闲状态观测中，相关进程的专用工作集合计约 120 MiB，包含共享页面的工作集合计约 490 MiB。工作集简单相加可能重复计入共享页面，不能将后者直接解释为应用独占内存。

该观测来自特定机器和当时的运行状态，不是内存上限，也不是跨设备性能承诺。下载、转码、缓存、WebView2 版本及运行环境都会影响结果。v1.1.1 的轻量安装设计也不直接等同于更低的运行内存。

当前文档仅记录已知证据与限制。新增验证应补充测试环境、触发条件和观察结果，而不只写“测试通过”。
